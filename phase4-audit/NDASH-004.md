# NDASH-004 — Monthly Growth uses obsolete financial history

Severity: High. Status: repaired candidate; deployment/live verification pending.

Reproduced again on127: August2026 All Offices shows five table rows and15 zero currency cells across prior/current/delta production, with a green MEA integrated-data assurance. A read-only comparison of July/August across four offices confirmed all eight MEA net-production totals are zero while all eight current production API totals are nonzero; none of the eight collection totals match either. Backend113/service043 hashes were verified. No amounts, patient identifiers or credentials were included in the evidence output.

Root cause: monthlyGrowthService.js treats any legacy MEA row as authoritative, including obsolete zero financial fields. History and sparklines read the same stale source and otherwise silently substitute manual EOD entries. History also ends at today rather than the selected month. The loader retained old results on failures and lacked response-generation protection.

Targeted repair: only monthlyGrowthService.js and MonthlyGrowthTab.jsx. Read existing production, collections and patient summary APIs for exact calendar months. Preserve current ledger net-production and collection calculations; do not use the separate legacy precomputed monthly endpoint. Sum known selected office financial values; the all-office patient count uses the network summary because new-to-office counts can overlap. No financial data is recalculated or stored by this change. Share identical reads within a view, limit concurrency to four across views, and skip obsolete queued reads. Reject missing numeric fields/API failures instead of substituting zero or manual data. End12-month history and6-month sparklines in the selected month and selected office scope. Clear stale figures and guard results/errors/loading/cleanup by request generation; display a retry message. Update the provenance notice without changing table/chart business calculations.

Verification before deployment: seven focused canonical-service tests (five fail against old source), four request-order/error/cleanup tests, and the retained office-filter regression cases adapted to the intentional removal of manual fallback. All586 frontend tests PASS. Production source build PASS34.40s. Rocket854 confirms the same two-file scope. Actual compiled service fixtures verify canonical field selection, unique network counts, selected-year rollover, history/sparkline alignment, deduplicated bounded reads and missing-field rejection. Actual compiled loader fixtures verify old success/error suppression and current error handling. Full reverse reproduces127 byte-for-byte; all seven prior dependent modules only relink to the new entry. No backend, payroll, credentials, import, sync, authentication or business-data changes.
